# Детекция выдоха и требования к валидации

> Любые показатели качества в текущем MVP **требуют валидации**. Они не являются диагнозом или измерением функции лёгких.

## Признаки

Каждые ~80 мс браузер вычисляет:

- **RMS** — энергия/громкость кадра;
- **zero-crossing rate** — доля смен знака сигнала;
- **spectral centroid** — центр тяжести спектра;
- **spectral flatness** — шумоподобность спектра;
- **crest factor** — отношение пика к RMS для резких импульсов.

Профиль калибровки содержит средние значения фонового шума и активных кадров выдоха. Порог активности адаптируется к фону и силе выдоха ребёнка.

## Объяснимая логика MVP

- ниже персонального порога → `silence`;
- высокий crest factor + высокая энергия → вероятный `cough`;
- экстремальная энергия/спектр → `noise`;
- низкая плоскостность и тональная структура → вероятная `speech`;
- достаточная близость к калибровочному шумовому профилю → `breath`.

Игра делает мягкую техническую паузу только после устойчивой последовательности посторонних кадров (~1,2 с), а не после одного кадра. Пауза не останавливает сессию: таймер замирает, монеты и прогресс сохраняются, шарик покачивается, а после ~0,8 с спокойного сигнала полёт продолжается сам. Формулировка нейтральная — «Микрофон слышит другой звук. Подождём тишины», без обвинений и без потери прогресса.

## Почему возможны ошибки

Возраст, микрофон, расстояние, комната, насморк, дыхательный паттерн и сопутствующие звуки существенно меняют признаки. Эвристики могут:

- спутать тихую речь с выдохом;
- принять резкий выдох за кашель;
- не услышать слабый выдох на шумном фоне;
- неодинаково работать на разных устройствах.

Поэтому это техническая пауза, а не «проверка на честность»: ребёнок ничего не теряет, игра сама возобновляется.

## Агрегаты сессии

Файл `src/game/sessionMetrics.ts` считает только агрегаты. Покадровые ряды живут внутри текущего breath-сегмента и стираются при его закрытии. **Сырое аудио не записывается, покадровые ряды не сохраняются и не передаются на сервер.**

| Метрика | Правило |
| --- | --- |
| `completedBreaths` | непрерывные breath-сегменты не короче порога |
| порог | по умолчанию 1.5 с, диапазон 0.5–10 с, шаг 0.1 |
| `averageBreathDuration` | среднее по завершённым сегментам, иначе `null` |
| `averageStability` | 0–100, среднее по сегментам, иначе `null` |
| `averageLatencyMs` / `maxLatencyMs` | интервал «первый breath-кадр → игровой кадр, применивший подъём» |

Формула ровности дыхания (**требует валидации**), первые и последние 15 % кадров сегмента исключаются:

```
CV = σ / max(μ, 0.10)
D  = mean(|sᵢ − sᵢ₋₁|) / max(μ, 0.10)
V  = 0.7 × min(CV / 0.40, 1) + 0.3 × min(D / 0.25, 1)
Stability = round(100 × (1 − V))
```

Пороги 0.40, 0.25, 0.10 и доля обрезки 15 % подобраны эмпирически и клинически не проверены.

Задержка — **техническая метрика программного конвейера**, измеренная через `performance.now()`. Она отражает время «детекция → отрисовка» и не является физиологическим показателем времени реакции ребёнка.

## Совместимость старых сессий

`birdBumps` и `obstaclesAvoided` исключены из DTO, API, UI, CSV и аналитики. В SQLite колонка `obstacles_avoided` сохранена ради безопасной миграции, но не читается. Для записей, созданных до появления новых метрик, API возвращает `null`, а не `0`. Все SQL-запросы используют явные списки полей — `SELECT *` не применяется.

## План валидации перед реальным применением

1. Утвердить протокол и endpoint labels вместе с клиницистами и специалистом по детской безопасности.
2. Получить информированное согласие и этическое/правовое одобрение сбора датасета.
3. Отдельно оценить возрастные группы, заболевания, языки, устройства и уровни фонового шума.
4. Разделять train/validation/test по детям, а не по аудиофрагментам.
5. Считать sensitivity/recall для выдоха, false-stop rate, confusion matrix и доверительные интервалы.
6. Отдельно тестировать речь, крик, кашель, плач, телевизор, улицу и несколько голосов.
7. Определить допустимый false-positive rate с учётом вреда от прерывания ребёнка.
8. Провести usability-тесты дружелюбности сообщений с детьми и законными представителями.
9. Версионировать алгоритм и хранить версию вместе с агрегатами сессии.
10. После запуска мониторить drift без сбора сырого аудио либо по отдельному согласованному исследовательскому контуру.

## Путь к ML

Рекомендуемый следующий подход — небольшой on-device классификатор над log-mel признаками или версионированным набором агрегатов. Модель должна запускаться локально, иметь fallback к калибровочным эвристикам и model card. Перед её появлением нельзя заявлять, что система надёжно распознаёт все виды нежелательных звуков.
